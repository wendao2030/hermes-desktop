# QQ搜索后按回车键的重要教训
**日期**: 2026年6月4日  
**发现者**: Hermes Agent  
**验证环境**: Windows 10, QQ桌面版

## 问题发现

在给好友"朱智聪"发送测试消息时，经历了以下问题：

### 第一次尝试
**流程**: 搜索"朱智聪" → 直接输入消息 → 发送  
**问题**: 消息发送给了错误的窗口/对象  
**用户反馈**: "你搜索朱智聪后没有选中他，导致你发的对象不对"

### 第二次尝试  
**流程**: 搜索"朱智聪" → 按方向键↓ → 按回车 → 输入消息 → 发送  
**问题**: 消息发送给了其他联系人  
**用户反馈**: "还是有问题，你还是在选中了朱智聪之后，又跳到其他的聊天界面了，是不是你点击了向上或者向下的箭头？"

### 第三次尝试（成功）
**流程**: 搜索"朱智聪" → **直接按回车键** → 输入消息 → 发送  
**结果**: 成功（等待用户验证）

## 关键发现

### 1. QQ搜索行为分析
- **搜索后第一个结果默认被选中**（通常是搜索的联系人）
- **按方向键↓会选中第二个结果**，导致错误
- **直接按回车键**选择第一个结果（正确做法）

### 2. 视觉模式 vs 文本模式的差异
当使用`mode='ax'`（文本模式）时：
- **无法看到**搜索结果列表
- **无法判断**哪个结果被选中
- **必须依赖**标准化的键盘操作

### 3. 正确的键盘导航模式
```
搜索 → 回车（搜索） → 等待2秒 → 回车（选择第一个结果）
```

**错误模式**（避免）:
```
搜索 → 回车（搜索） → 方向键↓ → 回车（选择第二个结果）
```

## 经验教训

### 1. 标准化操作流程的重要性
即使QQ"可能"会自动进入聊天界面，但为了确保可靠性：
1. 搜索后**必须**按一次回车键
2. **不要**按方向键
3. 等待界面加载（2秒）

### 2. 用户反馈的价值
用户的两次纠正：
1. "没有选中他" → 需要选中操作
2. "跳到其他聊天界面" → 方向键导致错误

这揭示了QQ界面的实际行为模式。

### 3. 技能更新的必要性
原有的"搜索后自动进入"假设**可能不总是成立**，特别是在：
- 网络延迟时
- QQ版本差异
- 界面加载不完全时

## 更新建议

### 技能更新
在`qq-messaging`技能中，**明确添加**：
1. 搜索后**必须按回车键**选择第一个结果
2. **禁止使用方向键**导航搜索结果
3. 添加等待步骤确保界面加载

### 操作步骤修正
```yaml
原步骤:
  搜索 → 等待 → 输入消息

修正步骤:
  搜索 → 等待 → 回车（选择） → 等待 → 输入消息
```

## 验证方法

### 1. 直接验证
- 请求用户检查消息是否发送给正确的人
- 如果用户说"没有收到"，立即重新尝试完整流程

### 2. 间接验证
- 所有工具调用返回`ok: true`
- 但`ok: true`**不等于**操作成功
- **必须**获得用户最终验证

### 3. 流程验证
- 如果连续两次失败，检查流程是否正确
- 特别检查：是否按了方向键
- 特别检查：是否按了足够的回车键

## 总结

**核心教训**: 在QQ搜索后，**直接按回车键**，**不要按方向键**。

**验证原则**: `ok: true` ≠ 成功，**必须**获得用户最终验证。

**标准化**: 即使界面"可能"自动进入，也要执行标准化的选择操作以确保可靠性。
